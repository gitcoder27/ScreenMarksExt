# SceneMarks — Agent Instructions

SceneMarks is a local-first Chromium (Manifest V3) browser extension for saving timestamp bookmarks and scene ranges on HTML5 streaming video pages. Vanilla JS with no build step, no bundler, and no npm dependencies — automated tests use only Node's built-in test runner. The repo root itself is the loadable extension.

## Repository Layout

- `manifest.json` — MV3 manifest. Permissions: `storage`, `unlimitedStorage`, `activeTab`, `scripting`, `tabs`, `offscreen`, plus `<all_urls>` host permission; content scripts run on all pages at `document_start`. Four browser commands (Chrome's maximum with suggested keys): quick save, range, library, `toggle-voice`.
- `src/shared/` — classic-script IIFE modules that attach to the global `SceneMarks` namespace: `constants.js`, `time.js`, `ids.js`, `schema.js`, `storage.js`, `migrations.js`. Load order matters (constants → time → ids → schema → storage). `migrations.js` is loaded only by the service worker (it needs `SiteAdapters`, so the worker's `importScripts` also loads `site-adapters/` before it) — it is NOT in the content-script load lists.
- `src/content/` — `video-detector.js`, `overlay.js` + `overlay.css`, `content-script.js`, and `site-adapters/` (generic, netflix, prime-video, hotstar, youtube, index).
- `src/background/service-worker.js` — MV3 service worker: message routing, content-script injection fallback, tab management, and the single storage writer (STORAGE_RPC handler + `Migrations.runAll` once per extension load, gated by a `chrome.storage.session` flag so it also covers enabling a disabled extension, plus on install/update, browser start and import — not on every worker wake).
- `src/voice/` — voice commands, loaded only by the offscreen document and the options page (never content scripts, so not in the duplicated load lists): `voice-features.js` (pure VAD, MFCC, DTW, match decision; no DOM, no `chrome.*`; Node-tested), `voice-capture.js` (mic → AudioWorklet → VAD, shared by the engine and Options training), `capture-worklet.js`, and `offscreen.html` + `voice-engine.js` (the always-on listener).
- `src/popup/`, `src/options/`, `src/library/` — extension pages (plain HTML/CSS/JS, no framework). Voice UI lives in `popup/popup-voice.js` and `options/voice-options.js`.
- `test/automated/` — dependency-free Node tests for the shared layer (schema, storage, migrations, time), the service worker's migration hooks and Open Random cap, the video detector's `seekTo` (fake media element), and voice (`voice-features`, `voice-engine`, `voice-pages`; `voice-synth.js` generates deterministic synthetic words that pass the real VAD and matcher). The storage double in `helpers.js` logs every get/set/remove with its keys, so tests can assert what a write touched. Run: `node --test test/automated/*.test.js`.
- `test/voice-bench.js` — manual (macOS-only) recognition bench: speaks the commands, look-alike words and sentences with eight `say` voices and runs them through the real VAD and matcher. Run it before and after any change to `voice-features.js` or the decision rule; the synthetic tests cannot measure recognition.
- `test/manual-html5-video.html` — manual test page for local video playback.
- `assets/icons/` — extension icons.

## Commands

There is no package.json, build, or lint setup. Automated tests cover the shared data layer:

```
node --test test/automated/*.test.js
```

To verify changes by hand:

1. Load the repo root unpacked in Brave (`brave://extensions` → Developer mode → Load unpacked) or Chrome.
2. After edits, click Reload on the extension and reload any open video tabs.
3. Test on `test/manual-html5-video.html` first (enable "Allow access to file URLs" when loading from `file://`), then on Netflix / Prime Video / Hotstar / YouTube. `README.md` has the full manual test checklist.

## Architecture Rules

- **Script load lists are duplicated**: any new JS file must be added to `manifest.json` `content_scripts[0].js` AND `CONTENT_SCRIPT_FILES` in `src/background/service-worker.js` (shared files also go in the worker's `importScripts`), in the same order. Otherwise the popup-injected path diverges from the auto-loaded path.
- No ES imports in content/shared context. Each file is an IIFE `(function attachX(root) { ... })(globalThis)` extending `root.SceneMarks` (`SceneMarks.Constants`, `SceneMarks.Schema`, `SceneMarks.Storage`, `SceneMarks.Adapters`, …).
- **Storage is split per video (since schema 2; schema 3 changes generic identities).** `chrome.storage.local` holds one `video:<videoKey>` key per saved video, plus `settings`, `activeRangeDraft`, `pendingJump` (null when empty) and `schemaVersion`; key names live in `STORAGE_KEYS` / `VIDEO_KEY_PREFIX` in `constants.js`. Writes set only the keys whose normalized value changed, so a `storage.onChanged` event — which every open tab receives — carries one video, not the library. Keep it that way: never add a key that grows with the library (an index, a counter of all videos) or that every write touches. Schema 1 kept everything in one `scenemarksState` blob; only `migrateToSplitStorage` may read that key.
- Every write passes through the `normalize*` functions in `src/shared/schema.js` (`normalizeVideo`, `normalizeSettings`, `normalizeDraft`, `normalizePendingJump`; `normalizeState` is for the single-object import/export shape); new persisted fields must be added there (with `sanitizeText` length caps) or they are silently stripped.
- Reads: `getState()` reads every video; pass `getState({ videoKeys: [...] })` to read only those (plus the small keys), or use `getSettings()` / `getScenesForVideo()`. Anything that runs per page load or per storage event must use a scoped read. `storage.onChanged` listeners should look at which keys changed (`Storage.isVideoStorageKey`) and use `newValue` instead of re-reading.
- **The service worker is the single storage writer.** All writes are serialized by the FIFO queue behind `updateState`/`updateRawKeys`/`clearAllData` in `storage.js`. Mutators pass `updateState` a `{ videoKeys }` scope: the draft then holds only those videos (plus settings, draft and pending jump), and a mutator must not touch videos outside its scope, which it cannot see. Without a scope the draft holds the whole library — only for rare paths (a replacing import). Content scripts, popup, library, and options must mutate through `SceneMarks.Storage.createClient()` (reads stay local via `getState`/`getScenesForVideo`); mutating directly from another context reintroduces the lost-update race. The worker's `STORAGE_RPC_METHODS` whitelist must match `RPC_METHODS` in `storage.js`, and neither may ever include `updateState`/`updateRawKeys`/`upsertVideo`. Mutators (and `updateRawKeys` planners) may return `Storage.SKIP_WRITE` to skip the write (no-op migrations depend on this — an idle pass must write nothing, or every tab gets a pointless `storage.onChanged` event).
- Cross-context messaging uses `MESSAGE_TYPES` (`SCENEMARKS_*` prefix) from `src/shared/constants.js` — add new message types there, never as string literals.
- Site adapters only normalize video identity (`videoKey`, `canonicalUrl`, `title`) per platform; they never touch media streams. `site-adapters/index.js` picks the adapter and falls back to the generic adapter field by field. Valid platforms: `netflix`, `prime`, `hotstar`, `youtube`, `generic`, `unknown`.
- **Voice commands.** The mic lives in an offscreen document (`src/voice/offscreen.html`, reason `USER_MEDIA`) that exists exactly while `settings.voice.enabled` is on: the worker opens/closes it on settings changes and in the once-per-load pass (offscreen documents close on the same events that clear the session flag). Offscreen documents get only `chrome.runtime`, so the engine reads settings and templates through `VOICE_GET_CONFIG` and the worker pings it with `VOICE_CONFIG_CHANGED`; never add `chrome.storage` calls there. The worker accepts `VOICE_GET_CONFIG`, `VOICE_COMMAND` and `VOICE_IDLE_CHECK` only when `sender.url` is the offscreen document, so a page cannot drive tab switching. Status to the popup and options goes over the `VOICE_STATUS_CHANNEL` BroadcastChannel (engine publishes only while a page sends `status-request`), never `runtime.sendMessage`, so it does not wake the worker. Content-side `VOICE_ACTION`s are gated by `isActiveHere()` and toast only fixed text, times and counts.
- **Voice templates** live in the `voiceProfile` key (`normalizeVoiceProfile`: known commands, ≤ `MAX_VOICE_SAMPLES` takes of ≤ `MAX_VOICE_TEMPLATE_FRAMES` × `VOICE_MFCC_COEFFS` rounded numbers), outside the state model: written only by `saveVoiceSamples`/`addVoiceSample`/`clearVoiceProfile` through `updateRawKeys` (page-only RPCs), so state reads, export and a replacing import never touch it. A word is recorded as `VOICE_RECORD_TAKES` takes (prompted as normal, softer, quick); Options' test mode can add casual takes up to `MAX_VOICE_SAMPLES` with the atomic `addVoiceSample`, which keeps the recorded takes first and drops the oldest added one when full. Capture uses raw mic audio (`echoCancellation`, `noiseSuppression`, `autoGainControl` all false in `voice-capture.js`): noise suppression strips the consonants that separate words, and auto-gain pumps the room noise that ends an utterance. Any change to that audio path or to feature extraction in `voice-features.js` must bump `VOICE_FEATURE_VERSION` (old templates are then ignored and the UI asks for a re-record). `voice-features.js` mirrors `COEFFS`/`MAX_TEMPLATE_FRAMES` from `constants.js` because it loads without it; a test keeps them equal. The voice lineup (`voiceLineup`) and auto-off clock (`voiceLastActivityAt`) live in `chrome.storage.session`, not `storage.local`.
- Breaking storage changes require bumping `SCHEMA_VERSION` in `constants.js` (now 3) and adding a migration in `src/shared/migrations.js`, run from `Migrations.runAll` (order matters: the schema-1 split runs before the generic-key re-keying, which reads per-video keys). Migrations must be idempotent, keep the old data until the new keys are written, and prefer data already on the new layout (a write can land before the migration runs).

## Conventions & Gotchas

- Security: render user content (notes, tags, titles) with `textContent` only — never `innerHTML` — since content scripts run on all pages.
- `README.md` previously claimed no `<all_urls>` host permission and no YouTube support and pointed at a nonexistent install folder; those errors were fixed, but re-verify README claims against `manifest.json` when touching permissions or adapters — `manifest.json` is the source of truth.
- Page hotkeys are registered at `document_start` so sites can't swallow single-key presses; hotkey defaults and all settings live in `DEFAULT_SETTINGS` in `constants.js`. After changing hotkey code or config, video tabs must be reloaded. Adding a hotkey touches five places: `DEFAULT_SETTINGS.hotkeys`, `normalizeHotkeys` in `schema.js`, the dispatch chain in `content-script.js`, and the input + save logic in `options.js`/`options.html`. Matching is done against `event.code` (via `tokenToCode` in `content-script.js`), not `event.key` — `event.key` is layout- and Alt-composed (macOS Alt+Shift+S yields "Í"); the options recorder (`tokenFromCode` in `options.js`) stores the inverse mapping, so the two maps must round-trip when either changes.
- Site switches: `settings.extensionEnabled` (pause everywhere) and `settings.disabledSites` (domains, each covering its subdomains, capped at `MAX_DISABLED_SITES`) are checked through `Schema.isEnabledForHost`. In `content-script.js`, anything that acts on the page by itself (hotkeys, overlay, capture messages) must check `isActiveHere()`. Queued library jumps and popup jumps deliberately keep working. Popup and options change the list only through `setSiteEnabled`, an atomic RPC, never a read-modify-write of `disabledSites`. The worker keeps a per-tab OFF badge in sync.
- Queued Library jumps are opened through the worker's `OPEN_VIDEO_AT_SCENE` command. The worker allocates a blank tab, publishes `pendingJump.targetTabId`, then navigates it. `setPendingJump` is worker-internal, excluded from both RPC whitelists. Content obtains its own tab ID through `GET_TAB_ID` and checks ownership before seeking; the worker injects `sender.tab.id` into atomic consumption checks alongside the video key and request token. Never infer the destination from video identity or the active tab, and never guess an owner for legacy ownerless requests.
- `settings.voice` is nested like `hotkeys`: `updateSettings` merges it per field, so pass only the fields you change (`{ voice: { micDeviceId } }`). Popup/options set `enabled` explicitly; the `toggle-voice` shortcut uses the worker-internal `toggleVoiceEnabled` (decided inside `updateState`). A browser restart turns voice off unless `resumeOnStartup`.
- Range drafts (`activeRangeDraft`) and queued cross-page jumps (`pendingJump`) have TTLs (`RANGE_DRAFT_TTL_MS`, `PENDING_JUMP_TTL_MS`) and are dropped during normalization once expired.
